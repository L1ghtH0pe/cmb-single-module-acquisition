# 系统规格说明

## 目标

本文件定义 CMB 单模块高速并行数据获取原型的系统范围、硬件基线、链路约束和阶段目标。

当前阶段的唯一目标是：先把单模块 200 Hz / 5 ms 周期的数据生成、链路传输、接收、统计和最小落盘稳定跑通，再决定是否进入 PREEMPT_RT、UDP、多模块同步和量产硬件路线。

## 当前范围

当前明确纳入范围：

- 单模块闭环验证
- MS-01 x86 主线平台
- Ubuntu 24.04 LTS 原生 Linux
- 第一版数据面优先 TCP
- 5 ms 周期稳定性、帧完整性、日志与统计
- 24h / 72h 稳定性测试
- PREEMPT_RT 仅做失败后的 A/B 备选

当前明确不纳入范围：

- 19 模块同步
- 严格 PTP / IEEE 1588 同步闭环
- 最终量产硬件定型
- 长期归档系统
- 复杂回放平台
- FPGA / MPSoC 前端集成

## 硬件基线

### 发送端

推荐：MS-01 x86

建议配置：

- CPU：i5-12600H 优先
- 内存：32 GB 起步，建议 2 × 16 GB
- 系统盘：1 TB NVMe
- 数据盘：如要尽早做长稳测试，建议增加第 2 块 NVMe
- 光口：原生 10G SFP+

### 上位机

推荐配置：

- x86 Linux 主机
- 32 GB 内存起步
- NVMe SSD
- 10GbE SFP+ 网口优先

### 光纤链路

当前已知条件是短距离机房内链路，因此第一阶段优先采用：

- 多模光纤
- 1000BASE-SX 或 10GBASE-SR 模块
- LC-LC 双芯跳线

原则：光模块、网口、交换机三者的速率和类型必须匹配。

## 总体开发策略

当前采用 **Windows 编码、Ubuntu 测试** 的两阶段工作流：

- 日常软件开发可先在 Windows 环境完成，重点推进 C++ 工程骨架、协议结构、日志模块、解析模块和基础单元测试
- Linux 机上的 MS-01 不作为第一开发机，而作为环境验证机、链路验证机和长稳测试机
- 一切和真实验收相关的结论，必须以 Ubuntu 24.04 LTS 原生 Linux 上的结果为准

这意味着：

- 在 Windows 下可以先完成 sender / receiver 的基本逻辑
- 但 5 ms 周期稳定性、SFP+ 光纤链路、TCP 长尾、CPU/IRQ 干扰、24h/72h 稳定性，必须搬到 Linux 上验证
- Windows 下的测试结果只能说明“代码逻辑大致正确”，不能替代 Linux 环境验收

## 阶段路线

### Phase 0

单模块物理闭环。

重点验证：

- 光纤链路可用
- TCP 帧流可解析
- 5 ms 周期是否稳定
- 最小日志和统计是否完整

### Phase 1

单机逻辑扩展到多逻辑模块模拟。

重点验证：

- 协议头语义
- 帧边界与重组逻辑
- 日志、统计、落盘结构

### Phase 2

多物理源 + 交换机 + 上位机汇聚。

重点验证：

- 多链路汇聚
- 突发流量影响
- 长时间稳定性

### Phase 3

真实探测器前端接入。

重点验证：

- 前端接口适配
- 本地缓存与节拍一致性
- 是否需要进一步下沉到实时核或 FPGA

## 当前关键未决项

- 端到端延迟的正式验收阈值
- 真实探测器前端最终接口类型
- 是否需要国产化约束
- 是否需要工业温度、无风扇、长期供货、固定 BOM
- 多模块阶段是否引入 PTP、硬件时间戳、UDP 数据面
